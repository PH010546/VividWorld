# 鮮活世界：各有其道

*Vivid World* · *[English](README.en.md)*

《Mount & Blade II: Bannerlord》的單人模組：卡拉迪亞的人會彼此發生事情、口耳相傳、各自判斷信不信、記住也會忘記，玩家是這張網裡的其中一個節點。

這份 README 寫給想讀程式、改程式、或想知道它到底怎麼運作的人。只想玩的話，[Nexus 介紹頁](https://www.nexusmods.com/mountandblade2bannerlord/mods/13395) 比較好讀。

---

## 核心設計：事件與「知道這件事」是兩回事

**事件**是世界上確定發生過的事：誰、在哪、哪一天、做了什麼。它只記一次，記完整，之後不改。

**傳聞**是某一個人手上的那一份副本，而副本會失真。每轉述一手，事件裡的每一段事實（時間、地點、在場的人……）依各自的易失度決定會不會掉，所以傳到第六個人手上的版本，資料上就是比目擊者那份少。

整個模組沒有任何一處在問「這件事重不重要、要不要通知玩家」。玩家只是網裡的另一個節點，照同一套規則聽到傳到他身邊的事；沒人告訴他，他就不會知道。

## 架構

```
VividWorld.Core    netstandard2.0   規則本身。不參照任何遊戲型別。
VividWorld.Module  net472           接遊戲的那一層：戰役事件、對話、介面、Harmony 補丁。
```

`Core` 只認得字串 id，不知道 `Hero` 是什麼。傳播、遺忘、信不信、恩怨、句子組成全部在 `Core`，所以整套傳聞系統可以在不開遊戲的單元測試裡跑完（目前兩千多條）。
`Module` 是唯一碰得到 Bannerlord 的地方：讀戰役狀態、交給 `Core` 純值、再把結果變成對話、日誌與畫面。

三條不能破的規則：

1. **Core 不參照遊戲**——有檢查會擋
2. **Core 不自己擲骰**——所有隨機都走以戰役、日期、決策內容為種子的確定性亂數。讀檔重來要得到同一個世界
3. **程式裡沒有可調的數字**——都在 `config.json`，有預設值與夾值；舊的設定檔只補新鍵、不改玩家的值

## 一則消息的一生

1. **發生**：來源有三種——
   - 遊戲本身的大事（死亡、被俘、獲釋、結婚、生子），依死因與經過細分
   - **情境**：資料檔描述的場景（條件 → 分支），依參與者的個性加權決定走向
   - **編的話**：有怨、爭位子、替自家人說好話的人，會產生「沒發生過」的事件，型別與句子跟真的完全相同，只差資料上的一個旗標
2. **傳開**：六條通道分兩組。見面（同隊伍、同軍團、同聚落）不是自己選的，好感幾乎不影響；遠端（同家族、嫁出去的親人、同王國）是自己選要寫信給誰，好感影響很大。遊戲時間定時跑一輪，限定名額輪流開口，每人挑一則。醜事講不講，看說話的人、聽的人各自跟出醜的人是什麼關係
3. **判斷**：聽到的人先判斷信不信——看他跟被說的人、跟告訴他的人交情如何，以及這件事像不像那個人會做的。被說的人可能否認，知道實情的人可能出面澄清，聽過的人會重判
4. **結算**：信了的人依事件的份量改變對當事人的好感（親眼全額、每多一手遞減）。摩擦另外記進模組自己的恩怨帳本；積怨夠深而且牽涉族長或其血親，才升級成兩個家族之間的恩怨
5. **遺忘**：每個人記多久 = 跟當事人的關係 × 事件份量 × 被反覆提起的次數。全部知情者都忘了，事件存檔時就清掉（有恩怨的、還沒走漏的秘密除外）
6. **講給玩家**：玩家問、NPC 主動講、玩家拿聽過的事去探聽。每句話由「事實句 ＋ 說話者依個性與立場的感想」組成，句子全部在字串表裡

模組讀的好感一律是兩個人各自的值，不是遊戲換成族長之後的家族值。

## 對遊戲本身動了什麼

- **兩個 Harmony 補丁**，都只管「玩家與某人」這一對：讓這一對的好感不再被換成雙方族長之間的值；換族長時不把舊族長的好感重複加到新族長身上。可在設定裡關掉，回到原版
- 好感與家族恩怨透過遊戲自己的 API 寫入
- 其餘不修改遊戲的 AI 決策，不覆寫任何原生檔案

## 持久化：不寫進存檔

戰役資料存在模組自己的檔案裡（`Documents\Mount and Blade II Bannerlord\Configs\VividWorld\`），不寫進 `.sav`。所以移除模組不會讓存檔壞掉。

讀舊存檔靠**快照**：每次存檔產生一個代號並拍下當時的戰役資料，讀檔時找到對應的那份還原。讀回一個舊存檔，傳聞也回到那時候，世界不會知道「從那個存檔的角度還沒發生」的事。玩家在遊戲裡按 `F9` 管理快照。

舊戰役一律能直接繼續玩：持久化格式只增不改，讀到不認得的欄位原樣保留。

## 內容是資料，不是程式

`module/ModuleData/` 底下四個 JSON：事件模板、情境、情境產生的事件、感想類別。新增一種場景、一種消息，大多不必寫 C#——寫資料檔與字串就好。虛假傳聞的機制也照資料檔裡填的「誰難看、可以推給誰」自動套用到新內容上。

細節見 [`CONTRIBUTING.md`](CONTRIBUTING.md)。

## 給其他模組的介面

- **`VividWorld.Api.VividWorldEventApi`**：只用基本型別的靜態門面，用反射就能讀，不需要組件參照。有事件發生的通知、查某人知道哪些事、取事件 JSON。沒走漏的秘密一律查不到
- **AI 聊天模組**：目前只接了 Calradia Remembers。以反射綁定對方的型別並檢查介面版本，對不上就停用並在日誌講明原因；把 NPC 還記得的傳聞照他聽到的版本交過去

## 可觀測性

每個新行為都要能從日誌看出**為什麼**：輸入值、每一項乘數、**被排除的項目與原因**。日誌在 `Configs\VividWorld\log.txt`。
`config.json` 的 `debug.logTellerTurns` 打開後，每一次轉述都會寫進日誌。另有開發者工具可以在遊戲裡叫出各個系統當下的狀態。

## 建置

需要 .NET SDK 8.0 以上、本機安裝的 Bannerlord **v1.4.8**、以及同一個遊戲資料夾裡的 MCM。

```
dotnet build VividWorld.sln -c Release
dotnet test tests/VividWorld.Core.Tests
```

建置要求零警告。遊戲路徑的設定方式與 PR 的規矩見 [`CONTRIBUTING.md`](CONTRIBUTING.md)，各資料夾的分工見 [`docs/architecture.md`](docs/architecture.md)。

---

## 安裝（玩家）

1. 將 `VividWorld` 資料夾放進遊戲的 `Modules\`
2. **另需安裝 Mod Configuration Menu（MCM）**，排在本模組之前
3. 啟動器裡勾選 **Vivid World**，排在 Native、SandBoxCore、Sandbox、StoryMode 之後
4. Harmony 已內附

針對遊戲 **v1.4.8** 建置。設定在遊戲的設定畫面（MCM）或 `config.json`，兩邊是同一份。

## 相容性

- **NaN、Lowborn 這類「平民不應與貴族攀談」的模組**：偵測到時，傳聞模式「自動」會改用寫實，家族等級 0 問不到消息
- **Calradia Remembers**：見上方「給其他模組的介面」
- **Affairs of Calradia**：它的個人好感模式做的是同一件事，偵測到就不重複處理
- **接管對話開場白的模組**：對話選單會多一句「你剛才似乎欲言又止？」把話題引回

## 開發藍圖

依開發順序：

1. **親身捲入**（下一個）：玩家在場時能親眼目睹情境，並可擔任其中一個角色、由玩家選擇怎麼應對（取代依個性擲骰）；玩家的決定變成一則會傳開的事件。目前玩家一律不算目擊者
2. **秘密系統重做**：把「秘密本身」（內容、屬於誰、誰知道）與「揭露它的情境」分開建模。現有兩種「秘密是一則資訊」的類型暫停產生，等新模型轉換
3. **第三方事件與消息來源**：讓其他模組的事件（以及改換王國、叛變、攻城陷落這類原生大事）接進同一條傳播管線
4. **玩家也能開口**：玩家主動轉述、散播消息，走與 NPC 相同的傳播與信不信規則

另外兩個方向尚未排入順序：

- **更多事件與情境**：大部分只需資料檔與字串
- **實際遊戲狀態改變**：目前事件只影響好感與恩怨，未來讓結果觸及金錢、名望、影響力等原生狀態
